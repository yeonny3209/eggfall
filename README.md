# EGGFALL

드래곤 오픈월드 MMO — 기획서 v0.2 구현

> 모든 용은 서로 다른 스킬을 갖고, 세계에는 단 열두 개의 신성이 있으며, 그 열둘은 언제나 사냥당할 수 있다.

## 현재 상태: **Phase 0 — 단순 조작 버전**

기획서 §11 로드맵의 Phase 0(비행 컨트롤러)이 구현되어 있습니다. 처음엔 관성·실속·스태미나가 있는
항공기식 모델이었지만, 조작이 너무 어렵다는 피드백을 받아 **훨씬 쉬운 스펙테이터 캠 모델**로
바꿨습니다: 마우스가 보는 방향이 곧 날아가는 방향이고, 스태미나·실속·상승기류는 없습니다.

알·전투·네트워크는 아직 없습니다. §13.1 "한 세션 = 한 시스템" 원칙을 따릅니다.

## Phase 0 에서 구현된 것

**비행 모델** (`src/flight/simulate.ts` — Three.js 의존 없는 순수 함수)

- "스펙테이터 캠" 모델: 마우스가 정한 목표 시점을 실제 자세가 뒤쫓는다.
  성장 단계별 `turnPenalty` 가 그 추적 속도를 늦춰 **큰 용일수록 시점 반응이 굼떠진다** (§6.3 불변 규칙 유지).
- 목표 속도로 부드럽게 가감속한다 (순간 정지/출발이 아니다).
- A/D 는 시선의 피치와 무관하게 항상 수평으로만 이동 — 위를 올려다봐도 강제로 뜨지 않는다.
- 실제 지형과 충돌해 착지/이륙한다.

**월드** (`src/world/`)

- 8km × 8km 절차 지형. **렌더 메시 · 충돌 · 그림자가 모두 같은 `terrainHeight()` 를 쓴다** (`terrain.ts`).
- 랜드마크 첨탑 240개 — 속도감의 근거.
- 고층 경계에 구름층, 그라디언트 하늘, 지면 그림자.

**HUD** (`src/ui/hud.ts`)

- 속도 · 고도 · 층 표시, 착지 알림, 고속 스트릭 효과

## 구조

```
src/
  types.ts              기획서 §10 데이터 모델 — "AI 의 기억" (§13.2)
  data/
    balance.json        모든 수치가 여기 하나에 (§13.4)
    divines.json        12신성 = 데이터, 코드 아님 (§13.5)
  flight/
    simulate.ts         비행 물리 — 순수 함수, Three.js 없음
    input.ts            키보드 → FlightInput
    camera.ts           추적 카메라
  world/
    terrain.ts          지형 높이 단일 진실 공급원
    scene.ts            월드 구성
    atmosphere.ts       하늘 · 구름 · 그림자
    dragon.ts           절차적 드래곤 메시
  ui/hud.ts
tests/flight.test.ts    비행 시뮬레이션 테스트 21개
```

### 설계 원칙 (§13 지침 준수)

1. **타입 우선** — `src/types.ts` 가 계약. 여기 없는 개념은 존재하지 않는 것으로 취급.
2. **순수 함수 분리** — `simulate.ts` / `terrain.ts` 는 렌더링·네트워크와 무관. Phase 2 에서 서버가 그대로 재사용한다.
3. **시뮬레이션 ↔ 렌더링 분리** — 시뮬레이션은 고정 timestep(1/60), 렌더링은 rAF. 프레임률이 물리 결과를 바꾸지 않는다.
4. **모든 수치는 `balance.json`** — 코드 수정 없이 튜닝 가능.
5. **12신성은 데이터** — `divines.json`. 하드코딩하면 유지보수 불가.

### 개발용 콘솔 핸들

개발 빌드에서 `window.__eggfall` 로 상태를 들여다볼 수 있습니다.

```js
__eggfall.pause()      // 시뮬레이션 정지
__eggfall.pump(3)      // 3초분 수동 진행
__eggfall.state        // FlightState
```

## 다음 단계 (기획서 §11)

| Phase | 내용 |
|---|---|
| **1** | 알 스폰 → 운반 페널티 → 흡수 → 성장 → 외형 변화 |
| **2** | 멀티플레이 (Colyseus). **최난관** — 반드시 별도 세션 (§13.6) |
| **3** | 전투 + 속성 상태이상 6종 |
| **4** | 반응 시스템 + 절차적 스킬 생성기 + 자동 명명 |
| **5** | 바이옴 6종, 유성우, 3층 고도, 둥지 |
| **6** | 신성 알 12개, 각성 카운터, 왕관의 무게, 핵 강탈 |

`SeasonState` 와 `counters` 타입은 Phase 6 을 위해 §13 권고대로 미리 `types.ts` 에 넣어두었습니다.

## 기술

Three.js · TypeScript · Vite. 물리 엔진(Rapier)은 지형 충돌이 해석적 함수로 충분한 Phase 0 에서는 도입하지 않았고, 오브젝트 충돌이 필요한 Phase 1/3 에서 추가합니다.
